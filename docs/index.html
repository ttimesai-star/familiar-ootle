Familiar

A private, network-enforced allowance for AI agents on Tari Ootle. The agent can spend, but only up to the limits the owner set, only to payees the owner listed, and the owner can take the budget back at any moment. The Ootle engine enforces this, not the agent's code and not a server.

Source code (MIT) Live testnet run Threat model Run it yourself

The problem

The Ootle wallet daemon can already hand an AI agent an API key with scopes such as TransactionSend_<account>. A scope says what the agent may do, not how much: a key that may send may send the whole account. If the agent is prompt-injected, or its host is compromised, the limit is whatever the account holds. On a transparent chain the agent's wallet is also public: its balance, every service it pays and who funds it.

Familiar moves the limits into the chain and keeps the money out of sight.

How it works

Agentone-time key, assumed compromised. Builds a stealth spend and calls pay(spend).
→
Leash component caller is the agent key · not paused · nothing revealed · every output under the budget root or an allow-listed payee root · window limit on the covenant-proven amount · then executes the spend from its own frame
→
Outputspayee: stealth output under an opaque root
change: back under the budget root

Every budget UTXO

Amount hidden by a Pedersen commitment. Locked under a pure condition tree Script(root), no key path:

errand = component(<leash>) AND BalancePreserved(max) recall = public_key(<owner key>)

Owner

  • funds the budget from stealth UTXOs;
  • sets the rule, the payees and the budget root (owner key only);
  • pauses or resumes the leash;
  • recalls the budget through the recall leaf with a plain stealth transfer. The agent is left with nothing to spend.

What an observer sees

Visible

  • that a payment happened, its epoch and the leash component it went through;
  • the amount of each payment (the covenant proves the exact outflow in clear);
  • the window rule and how much of the current window is used;
  • the payee's condition root (the same root for repeat payments to one payee).

Hidden

  • the budget and what is left of it;
  • who the payee is behind its root;
  • who the owner is (one-time key, stealth funding);
  • that an owner recall path exists, until it is used.

Honest limits. Payment amounts are public. Repeat payments to one payee can be linked. The agent's fee coin can link its payments unless it is itself stealth-funded. The window rule is public. The leash bounds what a compromised agent can spend; it does not make the agent anonymous. Prototype, not audited.

Run it yourself

Engine tests run the template on the same engine validators run (tari_template_test_tooling 0.46, tari_template_lib 0.34). Every refusal test asserts the exact reason. The test engine needs about 2 GB of RAM.

git clone https://github.com/ttimesai-star/familiar.git
cd familiar

# engine tests (template + window arithmetic)
cargo test -p familiar-tests -p familiar_core

# the template as published (wasm32, then wasm-opt)
rustup target add wasm32-unknown-unknown
(cd templates/familiar && cargo build --release --target wasm32-unknown-unknown)
wasm-opt -Oz --enable-bulk-memory --strip-debug --strip-producers --strip-target-features \
  templates/familiar/target/wasm32-unknown-unknown/release/familiar.wasm -o familiar.min.wasm

# the whole testnet story: publish, leash, fund, pay, five attacks, recall
FAMILIAR_FUNDER=<account-secret-hex>:<view-secret-hex> \
  cargo run -p familiar-cli --release -- scenario familiar.min.wasm esmeralda_run.md

The funder is any Esmeralda account holding tTARI (familiar keygen creates one; fund it through the testnet faucet). The workflows in .github/workflows/ run the same commands.
