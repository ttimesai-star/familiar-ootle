## Verification & Audit Checklists

### 1. Coupon Mode Security & Enforcement (`templates/familiar/src/lib.rs`)
- **Per-Payment and Per-Window Limits**:
  - `pay_coupons` (lines 200–248) asserts `coupons <= self.max_coupons_per_payment` for single transactions.
  - `pay_coupons` delegates allowance accounting to `familiar_core::charge` using `self.coupon_limit` and `self.coupon_window_epochs`, properly updating `self.coupons_spent` and `self.coupon_window_start`.
- **Inclusion & Cross-Leash Proofs**:
  - Every input in `pay_coupons` is verified against `coupon_leaf()` (which locks the condition to `CallerContext::current_component_address()`) and `self.coupon_siblings`. This guarantees that non-coupons, budget UTXOs, or coupons from other leashes cannot be spent via `pay_coupons`.
- **Uncounted Outflows & Merging**:
  - `pay` (lines 129–134) checks `has_covenant(input)` (`BalancePreserved`), refusing inputs without covenant conditions (coupons). Coupons cannot leave uncounted through `pay`.
  - `pay_coupons` strictly validates outputs against allow-listed payee roots and explicitly panics if change outputs or non-payee outputs are present. Thus, coupons cannot be merged into change outputs or moved uncounted.
- **Privacy & On-Chain Information Leakage**:
  - `pay_coupons` asserts `spend.covenant_claims.is_empty()`, `spend.inputs_statement.revealed_amount.is_zero()`, and `spend.outputs_statement.revealed_output.is_none()`. No covenant claims or cleartext amounts are submitted or revealed on-chain.

### 2. Access Control & Window Arithmetic (`templates/familiar/src/lib.rs`, `core/src/lib.rs`)
- **Owner-Only Checks**:
  - `ComponentAccessRules` restricts `pause`, `resume`, `set_policy`, `set_payees`, `set_budget_root`, `set_single_use_payees`, and `set_coupons` to `rule!(public_key(owner))`.
  - `OwnerRule::None` prevents component-level owner overrides from bypassing method access rules.
- **Policy Changes & Window Alignment**:
  - `set_coupons` and `set_policy` invoke `familiar_core::restart_window` when modifying rules mid-window. `restart_window` carries over `seen.spent` and sets the window start to the current epoch, preventing window reset exploits when window parameters change.

### 3. Tap Template Security (`templates/tap/src/lib.rs`, `tests/tap.rs`)
- **Draining & Epoch Rate Limits**:
  - `take()` enforces `taken_in_epoch < per_epoch` and increments `taken_in_epoch` per take.
  - `taken_in_epoch` resets only when `Consensus::current_epoch()` advances (`now != self.epoch`).
  - Draining beyond `per_take x per_epoch` within a single epoch is blocked by on-chain assertions.

### 4. Client CLI & Secrets Management (`client/src/cli.rs`)
- **Secret Handling**:
  - Secret key pairs generated by `familiar wallet` are written exclusively to the designated state file (`me.json`) and are never printed to stdout/stderr or emitted in transaction logs.
  - State files holding secret keys are excluded from repository commits by `.gitignore`.

### 5. MCP Server Input Validation (`scripts/familiar_mcp.py`)
- **Command Injection Safeguards**:
  - `call_tool` passes arguments to `run()` as a list (`subprocess.run([BIN, *args], ...)`), avoiding shell invocation (`shell=True=False`).
  - Inputs such as `payee` or `reason` cannot execute arbitrary shell commands.

### 6. Documentation Claims (`THREAT_MODEL.md` & `README.md`)
- **Consistency**:
  - All claims regarding threat mitigations, privacy guarantees, coupon mode operations, single-use payees, and refusal messages accurately match the engine implementation and test suite in `tests/leash.rs`.
